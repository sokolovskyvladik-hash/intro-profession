В ходе практической работы я разобрался с назначением Git и удалённого репозитория: Git хранит историю изменений, а удалённый репозиторий позволяет публиковать коммиты и совместно работать с проектом. Основную версию проекта следует хранить в ветке master, а отдельные доработки выполнять в собственных ветках, чтобы не затрагивать основную версию до проверки. Commit — это зафиксированное состояние файлов с сообщением о внесённых изменениях; push отправляет коммиты в удалённый репозиторий. Для проекта на Python используется виртуальное окружение .venv, в котором устанавливаются зависимости отдельно от системного Python. Файл .env предназначен для локального хранения API-ключа, поэтому его нельзя публиковать в открытом репозитории; для этого файл добавляют в .gitignore. Если секрет уже попал в историю Git, добавление его в .gitignore само по себе не удаляет ранее опубликованное значение. В примере с OMDb API программа отправляет HTTP-запрос и получает ответ в формате JSON, из которого можно извлечь название фильма, год, жанр, режиссёра, актёров и рейтинг. Визуальные инструменты Git в IDE помогают просматривать изменения, выбирать файлы для коммита и работать с ветками, но важно проверять результат самостоятельно. AI-помощник может объяснить код и предложить улучшения, однако его рекомендации необходимо проверять запуском и чтением кода. В проекте базовая версия размещена в master, доработка вывода информации оформлена отдельной веткой и объединена через Pull Request, а эксперимент с .env оставлен в отдельной ветке env-feature. В дальнейшем я бы дополнительно проверил работу запроса с действительным OMDb API-ключом и добавил обработку сетевых ошибок и некорректных ответов API.
